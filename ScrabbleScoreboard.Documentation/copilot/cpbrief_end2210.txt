Architecture Decisions
Separate Databases Per Microservice

Decision:

Use separate PostgreSQL databases rather than a shared database with schemas.

Services:

Players Service
    ↓
Players Database

Results Service
    ↓
Results Database


Reasoning:

Stronger microservice ownership model
Simpler migration management
Cleaner demonstration architecture
Less setup complexity
Better aligns with AD Identity principles
Flat Entity Model

Decision:

Keep entities simple and persistence-focused.

Example:

Player
{
    Id
    DisplayName
}


Avoid:

Navigation Properties
Complex Relationships
Shared Object Graphs


Reasoning:

Better microservice isolation
Simpler persistence
Easier future service separation
Persistence Ownership

Decision:

Persistence remains inside each API project for the PoC.

Structure:

Player.Api
|
+- Persistence
     |
     +- PlayersDbContext
     +- Repositories

Result.Api
|
+- Persistence
     |
     +- ResultsDbContext
     +- Repositories


No shared persistence library at this stage.
