Angular Learning: Observable vs Array Refactoring Bug
Scenario

During Results page development, the application failed to compile with:

TS2740:
Type 'Subscription' is missing the following properties
from type 'ResultDto[]':
length, pop, push, concat...

Root Cause

The service had evolved from returning:

ResultDto[]


to returning:

Observable<ResultDto[]>


after API integration.

Original component code assumed immediate access to data:

this.resultDtos = this.resultService.getResultDtos();


This was valid when the service returned a plain array.

First Attempted Fix

A subscription was introduced:

this.resultDtos =
    this.resultService.getResultDtos()
        .subscribe(results => {
            this.resultDtos = results;
        });


However this produced the same compilation error.

Why?

Because:

subscribe(...)


returns:

Subscription


not:

ResultDto[]


The code was therefore attempting to assign:

Subscription


to:

ResultDto[]


which TypeScript correctly rejected.

Correct Solution
this.resultService.getResultDtos()
    .subscribe(results => {
        this.resultDtos = results;
    });


Key change:

The result of the subscription was no longer assigned.

Instead:

Observable
    ↓
Subscribe
    ↓
Result Arrives
    ↓
Populate Array

Conceptual Lesson

Three distinct concepts were being confused:

ResultDto[]

Represents:

The data itself

Observable<ResultDto[]>

Represents:

A future source of data


or:

"I will provide a ResultDto[] later."

Subscription

Represents:

An active subscription to the Observable


or:

A handle proving we are listening.

Why TypeScript Was Valuable

TypeScript identified the issue during compilation.

Without strong typing the application would have started successfully while assigning:

Subscription


into a variable expected to contain result data.

Potential outcomes:

Runtime exceptions.
Empty UI rendering.
Delayed failure elsewhere in the application.

TypeScript prevented a runtime defect by detecting the mismatch during development.

Wider Angular Lesson

This exercise highlighted one of the major conceptual hurdles for developers transitioning from traditional .NET development.

Typical .NET pattern:

var results = repository.GetResults();


Meaning:

The data exists now.


Common Angular patterns:

Observable<ResultDto[]>
Signal<ResultDto[]>
Promise<ResultDto[]>


Meaning:

The data may exist later,
or may change over time.


Understanding the distinction between:

Data
Observable
Signal
Subscription


is fundamental to understanding modern Angular state management.
